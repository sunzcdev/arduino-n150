## 一、蜂鸣器演奏链路（2026-09-25 完成）

### 结果

在 Arduino UNO R3 上用一只两脚无源蜂鸣器（D8 + GND）完整演奏周杰伦《晴天》主旋律：
**463 个音符事件 / 151.2 秒全曲**，本次实机演奏前 307 个（**102.0 秒**，主歌→预副歌→副歌→「拜拜」收尾），
**实测耗时 106.8 秒、退出码 0、零丢音**，段落时间戳与谱面节奏一致。

### 数据流

```
GitHub TwilightLemon/SunnyDays (Voice.cpp 的旋律编码 + 歌词注释)
        │  build_qingtian.py   解析 -30/-90/0/300/500/700/400/_ 记号，MIDI 音高 → 频率
        ▼
qingtian_notes.txt            463 行 `频率Hz 时值ms` + 39 行 `#SECTION 歌词句`
        │  scp → 行者
        ▼
qingtian_play.py              逐音符下发 p<Hz>,<ms>，按 (时值+14ms) 定速
        │  9600 8N1
        ▼
n150-uno-buzzer.ino           tone(D8, Hz) → delay(ms) → noTone；回显 [ok] tone …
        ▼
        🔉 蜂鸣器
```

### 硬件接线

| 蜂鸣器 | 接到 |
|---|---|
| 长脚（带 + 标记） | **D8** |
| 短脚 | **GND** |

两脚无源蜂鸣器可直接由 IO 驱动（20mA 以内），不需要电阻或三极管。
判别有源/无源：发不同频率，音高跟着变 = 无源（固件 `v` 命令内置此测试）。

### 固件命令（9600 波特，每条一行）

| 命令 | 作用 |
|---|---|
| `p<Hz>,<ms>` | 单音，`Hz=0` 为休止（仍占 `ms`）；回显 `[ok] tone <Hz>Hz <ms>ms` |
| `v` | 三音测试（262/523/1047Hz），判有源/无源 |
| `m` | 播放固化在固件里的自作曲 |
| `0` | 立刻停 |
| `h` | 帮助 |

固件每个音符后自带 **12ms 间隙**；开串口会 DTR 复位板子并**自动响两声**（验接线）。

### 关键决策

1. **放弃视觉识谱**：让视觉模型"看简谱图片"再转音符，实测精度不可用（简谱识别错误率高，音准没法验）。
   → 改为取开源项目的**机读扒带数据**，再用第二份简谱交叉核对开头小节。
2. **只弹主旋律**：蜂鸣器单音，没有伴奏/和声/鼓点；音域裁到 G3(196Hz)–D5(587Hz) 最耐听。
3. **绕过驱动板**：原计划用 ULN2003 驱动板带电机，实测驱动板物理接触断路 → 本阶段改用蜂鸣器直插 D8，
   绕开驱动板故障先把"板子能被程序精确控制"这条链路走通。

### 踩坑记录

| 现象 | 根因 | 处理 |
|---|---|---|
| 新脚本打不开串口 / 读到别人的回显 | 上一轮调试残留的 `hold_probe.py` 已占口 29 分钟 | 演奏前 `fuser -v /dev/ttyUSB0` / `pgrep -af python3` 查占用并 `kill` |

| 担心远端跑的不是审过的版本 | — | 两边 `md5sum` 比对（本次 `qingtian_notes.txt` = `d3d55e3f…`，一致） |

### 能力边界（下一步的起点）

- **板子是哑执行器，大脑在主机**：换歌/加点歌服务/改段落**不用重烧固件**；只有"多音、音色、音量"要动硬件。
- `tone()` 硬限制：同一时刻单音（无和声）· 固定 50% 占空比（无力度/渐强渐弱）· 无包络（红白机音色）。
- 硬件升级三条路：① 8Ω 喇叭 + 三极管/RC 低通（音质质变，成本几元）；② 换 ESP32（I2S/DAC 真采样、多音轨）；③ 加第二通道做低音声部。
- **远端触发有抖动**：SSH/Tailscale 逐音符下发抖 30–60ms → 远程点歌要"整首歌先落到行者、本地常驻进程独占串口播放"。

## 一之补 A · 任意歌曲的通用链路（2026-09-25 晚）

《晴天》走的是「专门为蜂鸣器编码的旋律数据」（SunnyDays/Voice.cpp）；之后打通了**通用路线**：任意 MIDI → 单音化 → 蜂鸣器。

```
MIDI(.mid) ──build_song.py──▶ `频率Hz 时值ms` 音符表 ──play_notes.py──▶ `p<Hz>,<ms>` ──▶ 蜂鸣器
```

| 工具 | 作用 |
|---|---|
| `inspect_midi.py <mid>` | 先看轨结构（音域 / 最大同时音数 / 通道），挑出主旋律轨 |
| `build_song.py <mid> <out.txt> [--track 1] [--transpose n] [--min-ms 25]` | 按 tempo 图精确换算毫秒（支持变速）；把复音轨压成单音（每时间片取最高音）；合并同音、丢 <25ms 装饰音、补≥60ms 休止 |
| `play_notes.py <端口> <音符表> [起点] [终点] [遍数]` | 通用演奏器（**250000 波特**；主机 sleep = 时值+14ms 保证不排队） |
| `compare_melody.py` | 交叉核对两条数据源的旋律轮廓（判断抽取是否抓到主旋律） |

**实测**：《有何不可》（许嵩）MIDI 抽主旋律 → 691 事件 / 199.8 秒；副歌段 36.1 秒实放 38.1 秒，**听感确认「旋律都出来了」** ✓

数据源（都已实测可用）：

| 源 | 拿法 | 特点 |
|---|---|---|
| `artisdom/midi-piano` | 清单 `assets/midi_manifest.json`（2449 首）→ `gh api repos/artisdom/midi-piano/git/blobs/<sha>` 取本体 | 真 MIDI，inspect/build_song 全自动；注意钢琴编曲的「最高音」可能是琶音顶音 |
| `chiqingsan/SkyMusic` | `gh api repos/chiqingsan/SkyMusic/contents/<名>.txt` | 光遇扒谱 JSON `{time,key}`（Key0~14），专为人弹、旋律声部更干净 |

**坑**：中文常用词会让 GitHub **仓库**搜索失效（「有何不可」→505 条噪声）→ 改用 `gh api search/code -f q="曲名 filename:mid"` 等**代码/文件名**搜索（需 gh 已认证 ✓）。

## 一之补 B · 灯（3 颗 RGB，2026-09-25 晚）

`n150-uno-lights3.ino`：红 **D5** / 绿 **D6** / 蓝 **D9**（全是 PWM 脚）+ 蜂鸣器 **D3**。
- **共阴接法**：三颗灯短脚各串电阻（220Ω~1kΩ）→ 同一条负极轨 → UNO GND。图：`led_wiring.png`（脚本 `draw_led_wiring.py`）
- ⚠️ 红线：**正极绝不能并联后接一个 GPIO**（一脚 20mA 上限，三颗并联 ~40mA 超限且只能同亮同灭）。共用正极只能用 5V 轨（并需反转固件极性）
- 命令：`w1~w8`（流水/呼吸/轮转拖尾/心跳/全闪/渐隐交替/混色轮播/彩虹呼吸）、`c<r>,<g>,<b>` 直接配色、`l<n>,<v>` 单灯、`a<ms>` 步长、`0` 全停
- 开机自检：红→绿→蓝 依次亮 + 三灯同亮 + 蜂鸣器两声 → **接完线按 RESET 就能验接线**
- 8 灯版本 `n150-uno-lights.ino`（D2/D4/D5/D6/D7/D8/D9/D10）留档
- 事实：分开的三颗灯珠**不会视觉混色**，要真混色需光学扩散（紧挨着插 + 纸杯/白纸卷散光罩）；时间上的交替/渐变（w6/w7/w8）不需要任何额外零件
- **引脚映射可切并存 EEPROM**：`m0` = D5/D6/D9（全 PWM，推荐）· `m1` = D7/D8/D9（D7/D8 不是 PWM，红绿只能开/关）。切换后断电/复位都记得（EEVROM 0 号字节）
- ⚠️ **板载指示灯会污染三颗灯的颜色**：`D13` 的 "L" 灯**可由固件关掉**（`pinMode(13,OUTPUT); digitalWrite(13,LOW)`，已在 setup 里做）；**电源灯 "ON" 与 TX/RX 灯是硬连线，软件关不掉**，而且 **TX/RX 会随每个音符命令闪烁** → 播放时用黑胶带把板子那一侧贴住

## 一之补 B2 · 声光秀：灯随旋律变色（2026-09-25 晚）

`play_show.py <端口> <音符表> [起点秒] [终点秒] [遍数]` —— 弹旋律的同时把**音高映射成颜色**：

- 色相按**本段实际音域**动态撑满：最低音 = 红(0)，最高音 = 蓝(0.66)，中间走橙黄绿青；休止 = 全灭；时值越长越亮
- ⚠️ **别写死音高范围**：一开始写死 240~1100Hz，而本曲只在 262~698Hz → 色相只走了不到 1/3，蓝色全程没用上（打印出来全是 `RGB(255,x,0)`）。**把颜色打印出来看，是抓这类"参数与数据不匹配"的最快办法**
- 实测：《有何不可》70~130s 高潮段 = 193 事件 / 谱面 59.5s / 实放 59.9s，节奏完全吻合 ✓

## 一之补 B3 · 第二只蜂鸣器（双声部）与 Timer1 的三个坑（2026-09-25 深夜实测）

**做法**：D10 = OC1B，用 Timer1 **CTC 模式「比较匹配翻转」**生成方波 —— 纯硬件、不占中断、不抖。命令 `b<Hz>,<ms>`（第二声部），可与 `p` 同时响。

- ⚠️ **坑 1（元凶级）：CTC 模式下 OC1B 每个计数周期只翻转一次，不是两次。**
  所以计数器周期必须取 **1/(2f)**，否则输出频率**整整低一个八度**（请求 220Hz 实际 110Hz）。
  后果不只是发闷：压电片在**亚谐振区**被大幅低频摆动 → 振膜打壳/摩擦 → 用户听到的 **"刺啦"** 就是这个。
  改对频率后，两只蜂鸣器在三档频率下都干净 ✓ **排查顺序教训：先怀疑自己的数学，再怀疑硬件。**
- ⚠️ **坑 2：OCR1B 绝不能留 0。** CTC 下翻转点落在"计数归零"处时该匹配不可靠，会偶尔漏翻转 → 波形毛刺。
  正解：`OCR1A = F_CPU/(分频·2f) - 1`（=TOP=一个周期），`OCR1B = (OCR1A+1)/2`（半周期处翻转 → 50% 方波）✓
- ⚠️ **坑 3：分频 1 时低频会 16 位溢出**（16MHz/(2·220) = 72727 > 65535）→ **低于 244Hz 根本发不出来**。
  用分频 8（`CS11`）：可用 30Hz~1MHz ✓
- 已在播时**只改 OCR1A/OCR1B、不清零 TCNT1** → 换音无缝、无相位跳变毛刺 ✓
- 实测：**220Ω 串阻会把压电片音量削成"蚊子叫"** → 只在确认低阻抗负载时才试；两只同型号无源压电片直插引脚工作正常 ✓

### 追加：第二声部的最终形态 = **软件方波**（v6，2026-09-26 凌晨）

- ❌ **Timer1 硬件方案走不通**，根因是引脚归属：**蓝色 LED 在 D9 = Timer1 的 OC1A**，
  灯的 `analogWrite(D9)` 会把 Timer1 抢去当 8 位 PWM → 与低音声部**抢同一个定时器**，
  我写的 CTC/模式 14 配置因此永远不生效（实测现象：D10 **彻底没声**）。
- ✅ **正解：低音声部在 `loop()` 里按 `micros()` 软件翻转 D10** —— 不占任何定时器，
  Timer1 完整留给灯 PWM。用 `bassLastUs += bassHalfUs` **按半周期累加对齐** → 不累积漂移；
  抖动 = 主循环周期（10~30µs），对 150~700Hz 的低音 = 1~4%，听不出。
- ⚠️ **教训（通用）**：动手写定时器前先查**引脚归属**——
  **D9/D10 = Timer1 · D3/D11 = Timer2 · D5/D6 = Timer0**。同一定时器的两个通道无法各自独立定频。
- ⚠️ 流程教训：`arduino-cli compile … | tail -2` **会把编译失败的退出码吃掉**（管道取的是 tail 的退出码），
  于是"编译失败但照样跑了测试"。用 `set -o pipefail` 或在管道前显式判错。
  另外：**改完本地文件别忘了重新 scp** —— 曾出现"本地删了重复声明、远端还是旧文件"而白白多跑一轮。

## 一之补 C · 走过的死路（别再走）

**无源压电蜂鸣器放不出语音**（音频流方案实测结论）：压电片是窄带谐振器，靠**载波旁带**出声——62.5kHz 载波的旁带落在人耳之外（死寂），降到 7.8k/1.95kHz 只出蟋蟀/知了叫。要出人话必须换动圈喇叭/耳机；而**喇叭应挂小主机**（N150 自带 ALC897 音频口，已修 `audio` 组权限，`aplay` 实测通），**不该挂这块板子**。整条「语音」线因此从小主机走，板子只做音乐 + 灯。
